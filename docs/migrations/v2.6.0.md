# Migrating from v2.5.0 to v2.6.0

Nothing to migrate for finished work: runs, manifests, canonical suites, ADR rounds, Azure packages and reports written by v2.5.0 verify, render and export unchanged. The eight gates, the 17 expansion dimensions, the commands and the public schema version (`2.2`) are the same; the schema only gained optional fields.

## What changes for new runs

| Area | v2.5.0 | v2.6.0 |
| --- | --- | --- |
| Authority PDF without pypdf, scanned PDF, image or office document | refused at start, or silently UNSUPPORTED | planned for a reader; its native reading must transcribe authority that has no runtime text |
| Reader result `reading` | optional | required for plans written under `reading_policy: native-first/1`: `method`, `completeness`, `inspected`, `limitations` |
| SEQUENTIAL run with a PDF, image or document | went straight to Design | a short reading stage where the main model submits those files as `MAIN_MODEL` |
| Figures, tables, scans of authority | no place in the contract | `visual_facts` with a locator; Design gives each a `visual_fact_dispositions` entry; an identifier defined only there joins the ledger with `locator` |
| Catalog cache | reused by digest, role and contract version | also bound to the reading policy and the user transcription; older PDF/image/document catalogs are read again, older text catalogs reused as `LEGACY_UNASSESSED` |
| ADR files the runtime cannot extract | UNSUPPORTED / FAILED | `--transcription <path>=<text file>` after a native reading |

## Additive output fields

- `test-cases.json` → `sources[].reading` (`status`, `method`, `completeness`, `limitations`, `reader_role`) when a reading declaration exists.
- `identifier_dispositions[].locator` for an identifier defined only in visual content (it has no `line`).
- `gap_metrics.partially_read_authority_sources` only when a functional-authority source was read PARTIAL.
- Diagnostics `source_reading` (reading policy, statuses, native transcriptions, authority visual facts with their dispositions).

## Resumed runs

A reading plan created by v2.5.0 and resumed by v2.6.0 keeps its optional declarations and is never relabelled as natively read. To read such a corpus under the new policy, start a new run id; compatible text catalogs are reused.
